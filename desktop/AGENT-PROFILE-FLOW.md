# Noya 本机应用实例流程

核对日期：2026-10-28

## 定义

Claude Code、Codex、Claude Desktop、Claude Dot 等软件由用户自行安装和登录。Noya 不分发软件，不代理软件更新，也不要求运营端维护第三方软件版本。

客户端内置的是适配器：检测本机应用、生成固定 `127.0.0.1:17899` 的代理注入、隔离启动环境、绑定本地凭据槽位引用和记录启动状态。

应用适配器是能力定义，应用实例是用户创建的运行对象。一个适配器可以创建多个实例：

```text
Claude Code 适配器
  ├─ cc1 → 槽位 slot-1, slot-2 → 请求边界接力
  └─ cc2 → 槽位 slot-3          → 固定单号
```

## 用户流程

1. 点击“添加应用”。
2. 选择客户端内置的应用适配器，例如 Claude Code 或 Codex。
3. 客户端检测软件是否已安装、当前平台和适配器版本。
4. 输入本机实例名称，例如 `cc1`；名称只用于本机列表和事件，不会发送给运营端作为权限参数。
5. 选择本机凭据槽位引用和“额度用尽后接力”开关。凭据原文只写系统安全存储。
6. 客户端生成注入预览：代理环境、受控启动参数、实例状态和需要重启的提示。
7. 点击“生成注入并启动”；主进程校验适配器、设备会话、本机 17899 和 Noya 权益，然后启动第三方应用。
8. 应用列表展示 `cc1`，后续点击直接复用该实例；不重复填写代理或授权信息。

## 权限边界

- 用户可以创建、重命名、停用和删除本机实例。
- 用户不能在实例表单中填写可执行路径、任意命令、出口 IP、上游地址或服务端线路。
- 运营端只提供设备会话、套餐/流量、成员范围、接力槽位上限和策略；它不提供第三方软件，也不需要知道实例名称。
- 适配器更新只把旧实例标记为“需要更新”，不得在后台修改运行参数。
- `app-server`、`electron-profile` 等需要额外生命周期验证的适配器，先创建为待验证实例，启动保持失败关闭。

## 当前实现

`electron/agent-profiles.mjs` 已实现实例创建、别名冲突、适配器版本变更检测、代理注入物化和凭据槽位引用校验。它不读取或保存任何原始凭据。

真实桌面适配器仍需逐个验证；验证前可以完成实例建档和注入预览，不能宣称第三方应用已成功接入生产出口。
