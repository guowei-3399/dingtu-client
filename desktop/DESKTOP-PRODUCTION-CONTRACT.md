# Noya 桌面端生产接入合同

核对日期为 2026-11-12。本文记录桌面端实现拆解，接口、签名及验收以唯一三方主契约为准。当前交付状态见 `../docs/reviews/2026-11-11-用户端v112缺口与验收交接.md`。

> 三方主契约：[`../docs/contracts/00-noya-用户端-运营端-生产端三方接口契约.md`](../docs/contracts/00-noya-用户端-运营端-生产端三方接口契约.md)。本文是桌面端实现拆解，若与主契约冲突，以主契约为准。

## 结论

桌面端是当前主交付方向，目标为 Electron 的 Windows、macOS、Linux；手机端另做独立 App。用户端不直连运营数据库，不接收运营账号权限，也不向服务端提交出口选择。出口、身份和故障接管始终由服务端决定。

已经确定的接入链路是：

```text
Electron renderer
  -> preload 的窄 API
  -> Electron 主进程（设备会话、系统安全存储、原生内核）
  -> 运营端签发设备会话及一次性授权句柄
  -> 生产端接收句柄与设备证明，向运营端兑换授权副本
  -> 本机 sing-box 数据面（仅 127.0.0.1:17899）
```

当前网页 `/assistant/` 已实现其中的账号和只读数据部分；Electron 已完成设备会话主进程边界、配置读取门禁和本地 17899 supervisor 的安全生命周期接线，真实生产配置和出口 canary 尚未验收，不能把本地进程启动测试当成生产连接。

### 配置签发责任

运营端签发和撤销设备会话。桌面端通过该会话向运营端申请短时授权句柄，用设备注册私钥生成证明，再向生产端请求隧道配置。生产端向运营端兑换授权副本，核对本地绑定后签发配置，控制实际出口。用户端主进程负责验签、校验有效期及启停本机 17899。运营设备会话留在运营端请求边界。

新链路的接口、签名输入及错误处理以[三方主契约 §13](../docs/contracts/00-noya-用户端-运营端-生产端三方接口契约.md#13-v112-运营授权与生产放行)为准。现有运营端 GET 代拉配置是联调基线，生产入口、配置验签和已连接撤销待三端联调。

Agent 的无感接入和多订阅接力单独遵循 [AGENT-ADAPTER-CONTRACT.md](./AGENT-ADAPTER-CONTRACT.md)。每个 Agent 只做一次受控接入，之后由本地 supervisor 使用固定的 `127.0.0.1:17899`；另一个网站的 API 额度属于后续独立上游，不属于本合同的 Noya 服务。

### 17899 端口合同

`127.0.0.1:17899` 是 Noya 用户端唯一的本地应用接入点（v1.16 由历史端口 `7899` 迁至 `17899` 以避开第三方桌面软件冲突），提供本地 HTTP/SOCKS 入站给 Claude Code、Codex、Cursor 和其他已验证适配器使用。它不是公网管理 API、不是订阅下载端口，也不是任意目标的开放 CONNECT 代理。

sing-box 属于用户端 Electron 工作树的运行组件：工作树维护固定端口 supervisor、配置校验器、启动/停止生命周期和版本兼容测试；生产签发的配置作为运行时输入进入主进程。sing-box 二进制不提交到源码仓库，由桌面打包工件或受校验和保护的安装步骤提供。没有有效的生产配置时，客户端保持 17899 停止或 block fail-closed，禁止用示例配置代替生产配置。

- Electron 主进程负责绑定和生命周期；renderer、网页脚本和运营端都不能自行监听或改端口。
- 原生 sing-box/网络内核收到的身份、入口和出口授权由控制面签发；客户端不能通过代理请求参数覆盖出口。
- 应用模板只允许把 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 `NO_PROXY` 指向该本地端口；不得写入服务端上游、出口 IP、企业全量凭据或订阅秘密。
- `127.0.0.1:7890` 属于既有 CC/Clash 链路，Noya 不占用、不回退、不修改。
- 控制 API 通过受认证 HTTPS 地址访问；生产环境不把控制 API 绑定在 17899，也不接受从 17899 进入的管理请求。

## 已定下并已有实现

### 1. 账号与权限

- 网页端继续使用主站同源会话：`GET /api/v1/me`、`POST /api/v1/auth/login`、`/register`、`/logout`。CSRF 令牌只留在内存，不进 `localStorage`。
- 客户端以当前会话推导客户、企业成员和角色；不接受客户端传入的 `customerId`、出口 ID、成员角色或套餐等级。
- 企业成员权限由主站客户 API 和数据库 RLS 决定。普通成员只看到自己的授权范围，不能读取其他成员的出口或凭据。

### 2. 主站提供给客户端的只读数据

| 接口 | 作用 | 当前状态 |
| --- | --- | --- |
| `GET /api/v1/assistant/overview` | 当前客户的订阅状态、IP 配额、设备未知状态、服务端绑定摘要、身份数量 | 已实现并有契约校验 |
| `GET /api/v1/tenants/me/identities?limit=...&cursor=...` | 当前成员可见的连接身份目录 | 已实现并按 RLS 分页；只返回摘要，不返回 IP、节点或令牌 |
| `GET /api/v1/client/catalog?platform=...` | 运营发布的应用目录、平台模板、logo 校验值和 verified/beta/unverified 状态 | 已实现并有契约校验 |
| `GET /api/v1/tenants/me/members` | 企业成员只读列表 | 已实现并按角色过滤 |

这些接口不返回原始凭据、订阅令牌、代理密码、上游地址或可让客户端改出口的参数。`overview.egress.binding=server` 只表示绑定的权威来源是服务端，不代表隧道已经在线。

### 3. 应用目录

应用由运营端版本化发布，客户端按平台拉取并验证。应用名称、官方 URL、启动参数和环境变量均按白名单处理；模板是声明式数组，不能拼 shell 字符串。未验证应用不会显示为已接入，也不会被客户端自行补写包名或深链。

### 4. 企业本地凭据池

- 每个客户或企业成员拥有独立本地凭据池；企业管理员只能下发槽位数量、额度和策略，不能读取成员原始凭据。
- 客户端只保存槽位元数据；原始凭据只进入 Windows Credential Manager、macOS Keychain 或 Linux Secret Service。
- 凭据池按客户、成员、提供商隔离。成员不能读取原始凭据、手动借用其他成员槽位或改变服务端出口。
- 同一 Agent 会话保持粘性；只有服务商明确表示请求尚未接受且可安全重试（额度耗尽/可重试限流）时，才在请求边界串行切换下一个槽位。流式响应开始后不切换，认证/地区/安全策略拒绝不换号。

外部 API 网站的余额和 fallback 不在本阶段接入；未来只能作为独立 `external-api` 上游，通过后续接口合同接入，不能修改本地 17899 或出口绑定合同。

## 已实现的客户端链路与待验收环节

Electron 使用主进程设备会话，接口以三方主契约 §13 为准。当前客户端实现如下，正式服务端及制品回执仍需单独验收：

1. 系统浏览器授权码 + PKCE，使用 loopback 或受控 deep link 回到 Electron。
2. 服务端签发可撤销的设备会话（设备 ID、短期访问凭据、刷新凭据）；会话只由主进程使用。
3. 设备访问凭据、刷新凭据和设备证明私钥只写系统安全存储，renderer 不可见，诊断报告不包含秘密。
4. 主进程向运营端申请一次性授权句柄，再向可信生产 origin 提交句柄、issuedAt 和设备证明；按固定公钥验签后启动配置，不接受客户端出口或上游覆盖。
5. 主进程启动受版本锁定的 sing-box 内核，使用本机 loopback/TUN 入口；应用目录只负责声明如何启动目标 Agent，不包含任何秘密。
6. 客户端按签名到期停止转发；自动续期和服务端已连接撤销尚待联合验收。生产端不接收运营设备 token；出口/IP 必须来自服务端核验或明确的未知状态。
7. 出口故障由服务端健康检查和绑定策略确认后接管备用出口；客户端只接收结果，不执行自主换 IP。

下列路径是客户端当前使用的运营端接口基线。上线及部署状态须按各环境回执核对，新生产入口见三方主契约 §13：

```text
GET /api/v1/client/authorize
POST /api/v1/client/device/sessions
POST /api/v1/client/device/sessions/{deviceId}/refresh
DELETE /api/v1/client/device/sessions/{deviceId}
GET /api/v1/client/devices
POST /api/v1/client/tunnel/authorizations
POST /api/v1/client/tunnel/heartbeat
GET /api/v1/client/tunnel/status
```

生产端单独提供 `POST /api/v1/client/tunnel/config`。旧 r12 的运营 GET 配置路径仅为 v1.11 过渡记录。正式 trust origin/JWK 缺失、配置签名不符或服务端拒绝时，客户端停止转发；不能用 `/api/v1/assistant/overview` 冒充配置下发。`electron/control-client.mjs` 与 `production-tunnel.mjs` 分别处理运营设备会话和生产签名配置，不自行降级或伪造状态。

## 第一条生产验收垂直切片

当前以 Windows 免安装版完成“PKCE 登录 → 设备登记 → 授权句柄 → 生产配置验签 → 本地 17899 → 固定出口 → 已连接时服务端撤销”的正式验收，再完成 macOS/Linux 实机验证。手机端按独立 App 继续适配。缺少真实服务端或执行节点证据的环节保留待验收状态。

签名配置采用受限执行配置：网络 DNS、NTP、命名或内联 HTTP client、远程规则下载均须显式关联闭合代理图；系统 DNS、自动证书签发、Hysteria2 realm、实验管理 API、未知顶层网络组件及旧 GeoIP/Geosite 下载拒绝。DNS 劫持、主动解析及自动 ECH 查询需要配置受控 DNS。配置无 DNS 时只允许无需本地解析业务目标的代理模式，SOCKS4 需额外提供受控 DNS。生产入口域名的 bootstrap 系统解析属于当前明确边界，不据此宣称所有系统 DNS 已被接管。

这些策略通过本地正反例只能证明客户端拒绝不受支持的执行配置；正式生产配置的兼容性、辅助请求实际路径及出口一致性仍需固定制品后的受控 canary。签名配置校验的响应读取超时、取消和字节上限由主进程执行；辅助协议运行超时沿用 sing-box 配置和 supervisor 停止机制。
