# 定途连接助手

<!-- impeccable:product-schema 1 -->

## Platform

桌面 Electron 优先：Windows、macOS、Linux（Linux 目标为 AppImage 与 deb）。此目录仍是浏览器交互原型，不是可用的网络客户端；iPhone/iPad 与 Android 作为后续独立 App，不与桌面端共享原生实现。

## Users

个人银牌、金牌用户，以及企业账号下的成员。用户希望打开 Claude 等 Agent 后便捷使用，尽量避免端口、环境变量和配置文件操作。

## Product Purpose

目标是一次登录后连接授权网络并按需使用工具。当前账号资料与会话接入主站，网络配置、隧道和启动仍为演示。Agent 的官方账号、订阅和认证由用户在原应用完成。

## Capabilities and Constraints

- 计划内置 sing-box 核心；本原型不包含核心、不联网建立隧道、不修改本机网络设置。
- 网页 `/assistant/` 同源读取主站 `GET /api/v1/me`，复用 HttpOnly Cookie。真实昵称、邮箱、账号类型、等级与验证状态来自接口；`level=null` 显示未订阅，未知等级显示待配置。Electron 不复用该 Cookie，改用待实现的浏览器 PKCE/可撤销设备会话合同。
- CSRF 仅存内存；退出调用 POST /api/v1/auth/logout，携带 X-Requested-With: Dingtu-Portal 与 X-CSRF-Token。不另建用户表，不把会话令牌或 CSRF 放入 localStorage。
- 独立4177端口只做视觉预览，不跨源鉴权；仅展示禁用提交的内嵌账号表单。/assistant/ 通过同源API提交真实登录/注册，模拟角色不能覆盖真实账号。
- 应用较少，首页与应用库取消搜索，只保留类别筛选；原设置模块更名“我的”。
- 不依赖主站的本地能力已补齐：按平台保存主题、应用选择与分类、保存连接偏好；本机通知、帮助排查、脱敏诊断JSON下载及复制、官方入口、hash导航。存储仅保存设备偏好，事件限当前会话，不保存账号或真实连接授权。
- 客户端通过主站客户 API 读取 `/api/v1/assistant/overview` 和 `/api/v1/client/catalog?platform=...`；不直连运营数据库，不提交 `customerId`、出口 ID 或上游参数。服务端决定授权身份与出口绑定，客户端不能修改实际出口。
- 桌面端统一使用 Noya 本地代理 `127.0.0.1:17899` 连接已验证 Agent；7890 属于现有 CC/Clash 链路，不占用、不回退。17899 只承载本地数据面，生产控制 API 仍走受认证 HTTPS。
- 入口可以自动择优，出口保持粘性。只有服务端确认故障并存在授权可用备用资源，才接管出口；恢复不自动回切。
- 同一身份下的多个 Agent 共享该连接身份，不因选择应用而分配另一个 IP。
- 企业成员只看到自身授权身份。跨成员管理、购买和套餐管理属于网站管理页面。
- 每个 Noya 客户或企业成员可以在已获服务商授权的前提下添加多个订阅凭据，形成独立的本地凭据池；企业等级只决定槽位和策略权益，不代表成员之间共享凭据。凭据只保存在用户设备的系统安全存储中，不上传到主站或 Noya 服务端。服务端只接收脱敏槽位状态、额度摘要和切换事件。
- 凭据池按请求串行使用：一个 Agent 会话固定当前槽位，额度耗尽或服务端明确返回可重试的限流后，在请求边界切换到下一个可用槽位；流式响应中途不切换。认证失败、403、安全策略拒绝和地区错误不触发自动换号。
- 本地凭据池第一阶段只接入用户合法持有且服务商允许管理的订阅账号；外部 API 网站作为后续独立上游，不写入当前 sing-box/出口合同。成员不能读取原始凭据、手动选择槽位或借用其他成员的凭据。
- 各 Agent 的代理适配方式不同，尚待实际客户端开发验证；不能把系统代理等同于所有进程均已接入。
- 首次安装、系统网络授权和 Agent 官方登录不能承诺完全省略。

## Brand Commitments

沿用定途名称与线条波形标志。主站后台及登录参照 Linear，客户端采用下述独立参考图方向。

2026-10-22 用户明确调整：iPhone/iPad、Android 默认暗色，Windows、macOS 默认亮色。连接与启动应用是首页核心；详细连接路径和规则放到次级页面，不再在首页堆叠。先完善这一 UI 主流程，再扩充其他内容。

同日追加：客户端采用苹果式极简设计。此偏好替代本目录先前的 Linear 工作台式布局倾向；主站的后台与登录设计不在本次修改范围。以留白、动作层级、柔和圆角和精简文案表现，不添加与任务无关的装饰。

最新视觉依据为用户提供的《手机APP UI对标参考.png》：柔和灰紫背景、圆形头像、大圆角表面、彩色立体图标、轻柔阴影与底部中央凸起操作。该图片是风格与层次参考，不照抄其中的乱码文案或手机硬件外框。手机暗色、Windows/macOS 亮色的默认规则继续保留，浅色可手动预览。

已确认应用范围仅三类：编程（Claude Code、Codex、Cursor、Gemini CLI、GitHub Copilot），通用助手（ChatGPT、Claude、Gemini、Grok），任务 Agent（Meta Muse、Manus）。新增候选不等于完成原生启动或网络适配验证。

## Open Decisions

原生壳、核心分发与升级、各平台权限、各 Agent 精确适配和启动命令、是否复用 Karing 仍待开发评估。本次使用无依赖 HTML/CSS/JS 方便查看与移交，此选择不限定正式技术栈。浏览器响应式预览不等于已经交付 iOS 或 Android 原生客户端。Meta Muse保留既有候选，官方入口未核实前不提供网址。
